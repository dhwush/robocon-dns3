## 代码核对与有限复算

使用当前工作区 `classify.py`，将主相机区 `[176:1616,50:2610]` 缩放回1280×720，以HUD的x/y/yaw及取整俯仰复算，roll假定0，无原始深度。保留录屏叠字及框线。详细输出见 `replay_results.json`。

- 1号00:10：俯仰5.5°输出两层，6°和6.5°未知（RGB轮廓顶高不符）。00:15三档均未知（轮廓破碎/遮挡/直边未通过），尽管现场深度路径在该帧成功。说明纯RGB补救也存在姿态及轮廓敏感性，不能据此声称重现了现场深度错误。
- 6号00:40、01:40、02:00三帧，在±0.5°扰动下均输出两层，但方法在RGB局部盒面、接缝仲裁、黄地间切换。现场00:40两层、其余两帧未知。需要检查深度存在时的前景否决、上方空间和候选归属；不能直接用无深度复算覆盖现场拒绝。
- 5号01:40、02:00各三档均输出红顶。尤其01:40现场未知、无深度复算成功，说明该帧颜色与上下顺序本身足够；需要用原始深度和精确姿态核查深度归属分支。
- 5号00:40复算时，红3419px、蓝3065px，格内覆盖98.9%，但被“单色不是有面积的块状区域”拒绝，随后输出白盒两层。候选外框127×105，比01:40的106×78更大，提示连通块混入周围颜色或录屏标记。此项只证明当前复算的形状敏感性；录屏叠字会改变连通块，不能认定现场也由此拒绝。

代码对应：

- `classify.py::_rgb_cap_reading`：红蓝合并连通域→各色填充率/上下顺序→唯一归属；其中一种颜色与背景粘连，会因外接框膨胀而被拒绝。
- `classify.py::_assign_caps`：可靠深度优先决定归属，缺测或不落在任意塔体积内才回退RGB。可见的红蓝配对仍可能因深度归属到另一座塔而失效。
- `classify.py::_classify_cell.pack`：合格RGB顶块覆盖白盒结果；疑似顶块/上层物体会阻止回退为白盒层数。这会将候选轻微变化表现为“红顶/未知”或“层数/未知”。
- `view_field.py::suspend_for_radar`、`autonomous.py::suspend_sampling`：位姿不可用会清空当前稳定证据。`radar_pose.py`接收及匹配限制为数据年龄−0.05～0.60秒、图像位姿差≤0.15秒。

录像HUD的“位姿延迟”约0.9～1.8秒是在绘制时计算的端到端年龄，包含识别处理时间，不能直接解释为雷达传输耗时。当前机器用01:40裁切RGB做一次cProfile：全帧识别0.814秒，其中numpy.nonzero累计0.506秒，顶块识别0.333秒（含重叠耗时，不可相加）。只是单次无深度剖析，尚不能量化现场每个模块耗时。

## 建议处理顺序

1. 先拆分记录相机帧年龄、配对差值、识别耗时、位姿流状态、是否等待B启动。确保稳定观察确实开始，并区分状态文案残留与当前断流；不要直接放宽时间匹配门槛。
2. 1号：约束本塔最近白盒面的深度与连续顶边，排除后方纸板/柜体；对比70.1cm成功帧和98.9cm失败帧的原始点云归属。
3. 6号：用侧向观察分离前景；审查小局部盒面是否真有足够本塔支撑，以及有深度时是否误把前景作为整塔否决依据。
4. 5号：保存失败帧每个颜色候选的形状拒绝项、归属来源和实测世界坐标。先解决红蓝块与背景粘连及RGB/深度归属冲突，再决定是否需要阈值调整。

验证边界：此录像是带叠字的屏幕录像，无法恢复米制深度和精确重力数据。可以确认上述波动及拒绝现象，无法仅凭录像确定每一帧的唯一触发分支。
