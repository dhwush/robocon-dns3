# 3 号塔录屏 RGB 验证

视频：`/home/dong/2026-11-16 20-01-51.mkv`。

修改前 Git 快照：`be993d2`。该快照已包含工作区中按距离调整顶高容差、逐行补线、孤立接缝保护及显示框平滑的初步实现。此次在此基础上合并共线短段、按盒面/侧边支撑给同层候选评分，并在候选选择中排除孤立接缝。补线仍需双侧边和足够顶边宽度，避免将圆盘、齿轮、杂物识别为盒面。一层顶高保留 ±7.5cm 的限制；距离相关的额外容差用于两层候选，防止旧视频低处背景白面进入一层判断。

## 验证范围

保留原录屏颜色、识别框和叠字，未涂改图像。原始画面从 3200×2000 录屏的 `[432:1872,50:2610]` 区域裁切，缩放至 1280×720。使用 HUD 中的 x/y/yaw 和取整后的俯仰；没有原始深度，roll 按 0。因此这是 RGB 复算，不是原始 RGB-D 重放。

前四张帧分别加入 −0.5°、0°、+0.5° 的俯仰偏移，12 次均输出两层，并检查框位于实际盒顶附近。155 秒在 −0.5°、0° 时未知，+0.5° 时可得到两层；这一场景仍有姿态敏感性。

`rgb_35.png` 的实际顶边被原识别框覆盖，保持未知，不能把它记作成功识别。部分其他带叠字的连续帧也仍未知。当前验证不支持“整段视频每帧稳定识别”的结论。

## 复现

在仓库根目录运行：

```bash
PYTHONDONTWRITEBYTECODE=1 python debug_captures/rgb_validation_20261116_2001/replay.py
PYTHONDONTWRITEBYTECODE=1 PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest -q tests/test_tower3_stability.py tests/test_video_2001_tower3.py
```

`results.json` 保存快照与修改后结果、框坐标及诊断信息。`comparison.jpg` 左列为快照结果，右列为修改后结果；绿色框为此次复算输出，原录屏紫色/黄色标记仍保留。

最终完整回归：477 项通过。RGB 结果文件中的 `code_sha256` 与验证时的 `classify.py` 一致。
