# 雷达缺数据时沿用最近有效位姿

实时相机循环在雷达断流、数据过期或未能配对新画面时，保留最近一次成功配对的真实位姿，继续处理新相机画面；不改写时间戳，不将缓存值加入雷达历史，不伪造停稳采样。首次启动尚无任何有效位姿时仍等待真实数据。

只有此前已证实停稳时，缓存位姿才可延续识别。移动、转向、俯仰命令期间，以及停稳尚未成立或IMU姿态变化时，传入识别器的颜色/深度置空，不识别、不累计该帧证据。缓存位姿不能证明新的移动已经完成；停稳状态失效后，须由新雷达采样重新建立。移动期间断流会清空停稳窗口，恢复时仅使用暂停时间之后的采样。

保留原雷达有效性、时间戳与历史配对限制。沿用较新图像时不推进真实配对水位，因此延迟到达的有效雷达仍可恢复历史帧配对。界面提示缓存位姿状态，恢复后自动清除；地图显示继续沿用有效坐标。

修改：`view_field.py`、`report.py`。
验证：`tests/test_held_radar.py`，并扩展`tests/test_live_frames.py`覆盖GUI/无窗口及各雷达来源的断流与恢复。

针对性检查175通过。最后补充的恢复配对与缓存移动门控验证见`tests_recovery.txt`；全量见`tests_full.txt`。

限制：没有新雷达数据时，缓存无法反映未通过程序指令告知、且未引起IMU倾角变化的外部平移。程序不把缓存伪装成实时位置。

全量结果：686通过，1个既有侧向换位规划失败（`test_lateral_request_selects_reachable_view_with_real_parallax`）。最终恢复配对调整另由32项回归验证，无新增失败。
