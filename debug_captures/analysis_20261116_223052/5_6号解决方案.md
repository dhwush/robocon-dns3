# 5、6号解决方案

范围按用户补充修正：排除1号，移动时识别变化不算稳定性故障；只讨论相对稳定视角的5、6号。前一报告中的全局暂停提示不是本次归因前提。

## 6号：处理遮挡范围与候选归属

录像01:20诊断估距4.70m，写明前景遮挡、需要侧向视角。它的画面搜索区同时覆盖前景台面、4号附近白盒及后方场景。00:40曾通过RGB局部盒面输出两层，但很小的显示框本身不能证明识别错误：`_rgb_white_top`的piece本来只画顶边下面一条带，必须查看实际支撑像素才能判断候选是否可靠。

当前代码流程为：先计算RGB局部顶边，再用`_tower_clutter`检查整个投影区域；近处深度主判与`_upper_white_reading`失败后，`occludes=True`立即返回，后面的`_far_white_reading`没有机会执行。返回包装时已有合格RGB局部顶边仍可补救，所以不能说“遮挡必然否决全部结果”。实际存在远处白盒深度分离路径被整体遮挡判断提前截断的结构问题。

建议修改：

1. 把搜索区整体遮挡作为观察质量信息，另算候选盒面、候选顶边的遮挡与归属。下部被遮挡时，仍执行远处白盒分组，但不允许凭下部缺测确定层数。
2. 对候选要求同一深度表面的白盒支撑、真实顶边、合理层高；上方存在可靠本塔占用证据时拒绝。前景挡住上方采样射线只记“未观测”，不当成本塔上层物体，也不当作空域。
3. 证据不足继续未知并标记`needs_parallax`。使用现有侧向观察规划，优先找能把6号与前景分开的观察点；仅改变云台yaw/pitch不产生相机平移视差，无法保证解除遮挡。
4. 输出本塔支撑点数、候选深度、顶边/上方证据状态，避免用整个搜索区的深度有效率衡量6号可见性。

验收：下部遮挡、顶边和足够上部盒面可测时，正确识别；顶边未观测、只有中间接缝、前景属于4号、上方真实有物体时，不能误判层数。对原始连续RGB-D稳定片段统计正确率、未知率和错层率。

## 5号：先拆分颜色候选，再统一归属

录像01:40红蓝顶块清楚可见却未知；当前代码用同帧录屏RGB、HUD姿态和roll=0复算可以判红顶，±0.5°俯仰扰动也通过。说明该帧RGB有足够证据，但缺少原始深度，不能确认现场具体失败分支。

另一个00:40录屏RGB候选红蓝面积足够、格内覆盖98.9%，却被单色块状检查拒绝。这提示颜色粘连及形状校验值得处理；屏幕叠字可能参与粘连，因此它不是现场失败的定论。

建议修改：

1. 红、蓝分别提取块状核心，在空间邻近、横向重叠、上下顺序明确的条件下配对。检查配对核心的面积和形状，避免把连上的背景细条计入单色外接框后否决整个顶块。保留最小面积、细线排除和多候选冲突检查。
2. 在同一配对核心内做深度归属，剔除边缘混合像素。缺测、离散或明显穿透背景的深度不否决唯一RGB几何归属；可靠深度确证属于另一塔时保持冲突，不能直接强行采用RGB。
3. 同一套配对核心交给全帧归属和单塔读色，保持候选身份一致；同一顶块只允许属于一个塔。
4. 增加具体失败原因：颜色未成对、形状不合格、RGB归属冲突、可靠深度归属冲突。不要统一显示“没有合格候选”。
5. 单帧未知仍显示未知，累计确认继续由现有Vote处理。显示历史确认结果时应注明“已确认/当前不可见”，避免把上一帧红顶当成本帧观测证据。

验收：清晰红蓝配对、背景细线粘连、顶块深度缺测时能正确识别；单色背景、左右红蓝、细线配对、相邻塔顶块以及两个相当候选不能误认。最终必须在原始RGB-D稳定片段验证，录屏复算只作辅助。

实施顺序：5号候选拆分和归属诊断 → 6号候选级遮挡及远处白盒分离 → 稳定RGB-D片段回归。不先放宽HSV、层高或时间匹配阈值。
